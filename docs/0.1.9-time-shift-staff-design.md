# 0.1.9 归墟时移法杖（Time-Shift Staff）设计合同

> 本文件是 IS0.1.9 的实现合同与派发入口。实现仓库：`Code\ImmortalStorage`（canonical 源码 = 1.21.1 MDK 树，26.1.2 由 `project/version-compat/generate-compat-source.ps1` 生成）。
> 合同冻结后，任何偏离必须在本文档追加"合同变更"段落并标注取代关系。

## 1. 用户需求（原文摘要）

- 新增物品**归墟时移法杖**，合成台有序合成：`{空，仙锻合金，蕴灵晶，空，木棍，迷你仙墟，木棍，空，空}`（2026-10-20 用户更正：第二行第三格由「下界合金」改为「迷你仙墟」）。
- 无耐久，不可堆叠。
- 右键任意方块：为其添加一个**青色边框**，在**每一面中心悬挂一个青色加速倍率**，并为该方块提供**指定倍率的常驻单方块加速**。
- 再次右键该方块：消耗背包/仙窍中 **1 个混元一气**，边框改**红色**，悬挂字样改为红色 **1024x**，提供 1024x 单方块加速，持续 **60s（玩家真实时间）**，之后退回其之前的常驻档位。
- shift+右键（目标方块有常驻或 1024x 加速）：直接清空其**全部**时移法杖加速。
- 加速代码参考 **JDT**，且与仙窍全维度加速**兼容乘算**。
- 手持 shift+滚轮调整当前将要赋予的常驻档位：**2x / 4x / 8x / 16x / 32x** 共 5 档；手持档位调整**不影响**已经放出的常驻加速。

## 2. 已核实的参考实现（JDT，main 分支实测读取）

- `com.direwolf20.justdirethings.util.MiscTools#doExtraTicks(ServerLevel, BlockPos, double rate)`：取 `level.getBlockEntity(pos)`；若可加速，循环 `rate` 次，每次用 `blockEntity.getBlockState().getTicker(level, type)` 取 ticker 后直接 `ticker.tick(...)`；无 BlockEntity 但 `blockState.isRandomlyTicking()` 时循环内以 `1/1365` 概率调 `randomTick`（模拟原版随机 tick 期望）。
- `isValidTickAccelBlock`：无 BE 且不可随机 tick → false；有 BE 但取不到 ticker → false；方块命中 `TICK_SPEED_DENY` 标签 → false。
- `TimeWandEntity.calculateAccelRate(speed) = 2^speed`，即等级 1..5 → 2x..32x；本模组档位与此同构（2^(tier+1)），1024x = 2^10。
- JDT 用**实体**驱动额外 tick；本模组不能照抄实体方案：仙窍额外 pass 只调 `tickBlockEntities()`，不跑实体 tick，会破坏乘算。因此本实现挂在 `Level#tickBlockEntities()` 的 TAIL。

## 3. 实测确认的平台事实

- 1.21.1（NeoForge 21.1.235）：`net.minecraft.world.level.Level#tickBlockEntities()V` 为 `protected`；`ServerLevel#tick` 内部调用 `this.tickBlockEntities()`；`ServerLevel` 未覆盖它。
- 26.1.2（NeoForge 26.1.2.94）：同名方法为 `public`。mixin 注入点两代同名。
- 仙窍加速：`PersonalRealmServerLevel#tick` 先 `super.tick()` 一次，再对每个额外 pass 调 `RealmTickSafety.extra(this, this::tickBlockEntities)`。故在 `tickBlockEntities` TAIL 上叠加的额外 tick 会随 pass 数自然**乘算**。
- 既有安全设施：`RealmTickSafety`（线程局部作用域、最多 64 层、额外 tick 抛错隔离）、`RealmSafeBlockTicker`（`immortalstorage:time_acceleration_disallowed` 与 `c:tick_acceleration_disallowed` 标签拦截）。
- 既有标签文件：`data/immortalstorage/tags/block/time_acceleration_disallowed.json`（已存在，含通用与 IF Souls 标签）。本物品直接复用，不新建标签。

## 5. 数据模型（服务端权威）

### 5.1 档位（物品上的 DataComponent）

- 组件：`ModDataComponents.TIME_SHIFT_TIER`，类型 `Integer`，`persistent(Codec.INT)`，默认 0。
- `tier ∈ 0..4` → 常驻倍率 `2^(tier+1)` = 2/4/8/16/32。
- 物品缺少组件时按 0 处理（读取方必须用 `stack.getOrDefault(TIME_SHIFT_TIER, 0)`）。
- 手持档位只决定"下一次赋予"的倍率，不读写任何已放出方块。

### 5.2 方块记录（SavedData，按维度）

`com.immortalstorage.immortalstorage.timeshift.TimeShiftStore extends SavedData`，每个 `ServerLevel` 一份：

```java
public record TimeShiftEntry(int tier, boolean boosted, long boostEndEpochMillis) {
    public int permanentMultiplier() { return 1 << (tier + 1); }   // 2/4/8/16/32
}
```

- 存储：`Map<BlockPos, TimeShiftEntry>`。
- 序列化：`CompoundTag` 列表（`pos` long、`tier` int、`boosted` boolean、`boostEnd` long）。必须能跨存档重启恢复。
- `boostEndEpochMillis` 用真实时钟（`System.currentTimeMillis()`），不是游戏 tick——用户要求"玩家真实时间"。
- `boosted == true` 且 `now >= boostEnd` 视为已到期：运行时回落常驻档位并**清除 boosted 标记**（保留 tier），并广播同步。

### 5.3 可加速判定

`TimeShiftAcceleration.isAccelerable(ServerLevel, BlockPos, BlockState, @Nullable BlockEntity)`：

1. 命中 `immortalstorage:time_acceleration_disallowed` 或 `c:tick_acceleration_disallowed` → 不可加速。
2. 有 BlockEntity：`state.getBlock().getTicker(level, state, (BlockEntityType) be.getType())` 非 null → 可加速。
3. 无 BlockEntity 且 `state.isRandomlyTicking()` → 可加速（随机 tick 语义按 JDT：每次额外 tick 以 `1/1365` 概率触发 `randomTick`）。
4. 其它 → 不可加速。

### 5.4 有效倍率

```
effective = boosted && now < boostEnd ? 1024 : permanentMultiplier(tier)
```

加速调度在 `Level#tickBlockEntities` TAIL 执行，**每次 pass 对目标方块额外 tick `max(0, effective - 1)` 次**（正常 tick 已由原版在该 pass 内执行一次）。
因此：仙窍 4x（4 个 pass）× 常驻 16x → 实际 64 次 tick/游戏 tick，符合"乘算"。
随机 tick 方块同理：每次额外迭代按 `1/1365` 概率触发。

## 6. 行为状态机（右键）

判定顺序（服务端权威；客户端只发交互）：

| 当前状态 | 输入 | 结果 |
|---|---|---|
| 无记录 | shift+右键 | 无效果，动作条提示 `time_shift.nothing_to_clear` |
| 有记录 | shift+右键 | 删除记录 → 清空加速 → 同步 → 提示 `time_shift.cleared` |
| 无记录 | 右键，方块可加速 | 记录 = `{tier: 手持档位, boosted:false}` → 同步 → 提示 `time_shift.applied`（带倍率） |
| 无记录 | 右键，方块不可加速 | 提示 `time_shift.not_accelerable` |
| 有记录，未 boost | 右键 | 需要 1 个混元一气：成功则 `boosted=true, boostEnd=now+60000`（tier 不变）→ 同步 → 提示 `time_shift.boosted`；失败提示 `time_shift.need_primordial_qi` |
| 有记录，已 boost | 右键 | 需要 1 个混元一气：成功则 `boostEnd=now+60000`（续时）→ 同步 → 提示 `time_shift.renewed`；失败提示 `time_shift.need_primordial_qi` |

- 混元一气扣除顺序：玩家背包（items 0..35 主背包 + 副手）→ 若不足，从**仙窍**扣除（`PersonalStorageApi`/`PersonalStorageNetwork`，仅对拥有者）。
- 记录里的 `tier` 在 1024x 期间保持不变 → 到期自动回落"之前的常驻档位"。
- 方块被破坏/替换：记录保留无意义，调度时跳过不可加载位置；`TimeShiftStore` 在方块变化（`BlockEvent.BreakEvent` 或 `onBlockStateChange`）时清理，并在下一 tick 广播。
- shift+滚轮：客户端 `InputEvent.MouseScrollingEvent`；玩家潜行且主手或副手持时移法杖时取消原版快捷栏切换并发送 `TimeShiftTierPayload(delta)`；服务端把档位写入主手物品（`(tier + delta + 5) % 5` 循环）并同步。

## 7. 网络协议

新增两个 `CustomPacketPayload`（`ModPayloads` 内）：

```java
// S2C：某维度的全量时移记录
public record TimeShiftSync(int count, List<Entry> entries) implements CustomPacketPayload {
    public record Entry(long pos, int tier, boolean boosted, long boostEndEpochMillis) {}
}
// C2S：shift+滚轮档位调整
public record TimeShiftTier(int delta) implements CustomPacketPayload {}
```

- `TimeShiftSync` 只在服务端数据变化时发送给"该维度的所有玩家"，并在玩家登录/换维度时补发。
- 客户端缓存：`Map<ResourceKey<Level>, List<Entry>>`，渲染用；客户端不用它做任何权威判定。

## 8. 客户端渲染

- 事件：`RenderLevelStageEvent.Stage.AFTER_PARTICLES`（与 `DomainExpansionHighlight`、`ToolLocatorRenderer` 一致）。
- 边框：`LevelRenderer.renderLineBox` + `RenderType.lines()`，AABB `.inflate(0.002)`；青色 `(0.0f, 0.85f, 1.0f, 0.9f)`，1024x 红色 `(1.0f, 0.15f, 0.1f, 0.9f)`。
- 六面文字：每面中心（面中心坐标向外偏移 ~0.51）渲染 `"16x"`/`"1024x"`，文字朝该面法线方向；同色；距离 > 64 格跳过。
- 文字必须深度测试（被方块遮挡时不可见），且不写入世界深度缓冲导致其它渲染异常。
- 渲染仅在 `mc.level` 非空且不是 `mc.screen` 时执行。

## 12. 未决 / 已作出的解释性裁定

- **裁定 A**：右键"已常驻加速"的方块 = 升/续 1024x（用户原文顺序语义），不是"用新档位覆盖常驻倍率"。要改常驻倍率，先 shift+右键清空再右键重设。
- **裁定 B**：1024x 期间再次右键 = 再消耗 1 个混元一气并**刷新** 60s（续时），而不是叠加倍率。
- **裁定 C**：shift+滚轮为**循环**（0→1→2→3→4→0），避免到顶/到底时滚轮无响应。
- **裁定 D**：随机 tick 方块（作物/树叶等）同样可加速，按 JDT 的 `1/1365` 期望模型；可在配置关闭。
- **裁定 E**：1024x 每 tick 额外 1023 次 tick 是用户明确要求，不因性能做静默降级；防护措施 = 禁用标签 + 每维度记录上限 + 异常隔离。
